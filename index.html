But it was designed as a general‑purpose web server — reverse proxy, TLS terminator, load balancer, dynamic routing, the whole toolbox.

F‑STATIC is none of that.

F‑STATIC is a pure static‑file railgun — engineered to do one thing at maximum speed:

Serve files. As fast as physically possible.

Why F‑STATIC Beats NGINX at Static Files

1. Zero‑Overhead Architecture

NGINX handles every request through layers of modules, filters, and abstractions.

F‑STATIC uses a direct memory → socket pipeline with no middlemen.

2. GPU‑Accelerated Pinned Memory

Files are loaded into GPU‑pinned host memory for ultra‑fast DMA transfers.

NGINX can’t do that.

3. Multi‑Process SO_REUSEPORT Scaling

Each CPU core gets its own worker, its own socket, and its own OpenCL context.

No locks. No contention. No bottlenecks.

4. Epoll Edge‑Triggered I/O

F‑STATIC uses the fastest I/O model Linux offers.

NGINX uses a more general, compatibility‑focused event loop.

5. VRAM Promotion (Optional)

Hot files can be mirrored into actual GPU VRAM for near‑zero latency access.

NGINX has nothing even close to this.

The Result?

F‑STATIC pushes 100k–200k requests/sec on mid‑range hardware.

NGINX simply can’t match that for pure static files.
